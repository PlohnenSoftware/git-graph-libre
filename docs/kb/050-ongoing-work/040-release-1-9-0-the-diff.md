# Release 1.9.0 — "The Diff"

**Status: release preparation complete on local `the-diff` (`2026-10-19`);
no pushing. Every slice in scope is integrated — waves A–D, the whole
Phase 17 port (22a–22j, five-arm parity recorded), D45–D47, D48's agent
half, D50/D51 and all Sonar follow-ups — and the final wave gate is `OK`
with 0 new issues. On `2026-10-20` `the-diff` was rebased onto `main`
(which set the version to 1.9.0), with every original date kept; the
`[1.9.0]` changelog was written; and the `diff-1.9.0/*` sub-branches and
their worktrees were removed; the issue #32 fix was then integrated from
the `fix` branch, and issues #30 and #31 were fixed as D60–D63 with their
Sonar follow-ups D62F and D63F (see the integration log). Remaining, all the
maintainer's: D48's display half, D90's README, packaging, tag and
publication steps, D30's posting, and D07 when a gix release ships the
fixes.**

Everything about diffs that is open, in one release: what users asked for,
what the roadmap left behind, and what the `2026-10-18` diff audit found
broken. The work is cut into slices small enough for one agent session each,
with their files, steps, tests and acceptance spelled out, so several agents
can work in parallel. Any agent taking a slice must follow
[the agent protocol](040-release-1-9-0-the-diff/010-agent-protocol.md).

**One rule across all slices (decision X7, `2026-10-18`):** Git-compatible
results (file lists, renames, `+N/−M`) come from gix or Git and are fixed
upstream in gix where possible. What a diff *looks like* comes from the port
of VS Code's algorithm (Phase 17). The two are never mixed.

  among the features.
